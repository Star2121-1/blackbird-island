# 《黑鸟岛：筛子》

长篇推理小说《黑鸟岛》的视觉小说改编，全本：序章 + 二十四章 + 尾声，六天一夜读完的一份卷宗。

```
序章 2025·杭州（顾言笙翻开手稿）
  第一日  ch1 抵达 → ch2 → ch3 书房（第八个名字）→ ch4 → ch5 → ch6 大厅 · 第一轮
  第二日  ch7 → ch8 → ch9 → 八仙桌 · 第二轮
  第三日  ch10 → ch11 → ch12 → ch13 → 大厅 · 第三轮
  第四日  ch14 → ch15 → ch16 → 大厅 · 第四轮
  第五日  ch17 → ch18 → ch19 → 大厅 · 第五轮
  第六日  ch20 → ch21 → ch22 → ch23 → ch24 → 合上卷宗
尾声 2025·杭州
```

每天夜里合上手稿，回到市档案馆的阅览室，读一段顾言笙的调查笔记（`game/12_days.rpy`）。

## 玩的方式和弹丸论破不一样

弹丸论破的圆桌裁决奖励"指出凶手"。这本书的地基是不可知——终稿不点名。
所以本作的胜利条件是 **逼出多少沉默**：把一条证据抵在一句话上，让说话的人停下来。

- 五轮对质，合计 40 句话（7／9／8／8／8），留了破绽的是 2／3／3／3／3 句——
  全六日一共 14 处沉默可逼。打到几处算几处。
- 反驳机会：第一轮 3 次（教学局），往后每夜 4 次——多给一次，错一次还有余地。
- 失败不改变真相，只改变收尾那几句话。
- 沈南舟那一格是"反问"，不算赢：主人不会沉默，他把问题推回你手上。
  但抵中他，会拿到他亲口承认的那一句——第三十三条证据只在这里给，所以帮助页
  把这句写明了（不写，图鉴就永远差一格，而玩家不知道自己漏在哪个动作上）。
- 抵中了也不一定都是沉默：`hit_kind` 有三种——`silence`（涂黑条＋角章，计分）、
  `counter`（虚线框，反问）、`reveal`（翻开一条信息，不计分也不画停顿）。
  两种 reveal 的结算文案末尾统一一句"这不是谁停下来。是卷宗里多翻开的一页。"，
  免得玩家读到"他没有再说"却看见零分。
- 死亡时间在第三句才到手，却要用在第二句上：一圈听完会自动回到第一句，
  桌上写"第 2 遍在听"。也可以直接点名牌跳回某个人重听。
- 第八个名字在第三章被读到（"我没有看清"），在第十四章正面出现时给玩家拼——
  那是**反谜题**：无论怎么拼都拿不到，一律回"我没有看清"。
  这一屏是在教玩家——这本书不让你指认谁。

## 基调：界面就是那份卷宗

不是"游戏套一层纸的皮"。玩家翻的是手稿本身，岛上的照片是夹进卷宗的现场快照。

- 纸面 `#eae5da` 是唯一的阅读面；深色照片只当场景，字一律落在纸上。
- 牛皮纸底纹压 0.22：再深就把 20px 的小字一起压到 2.5:1 以下了。

颜色各有专司，不许串：

| 色 | 用途 |
| --- | --- |
| 墨 `#0b0d10` | 中性的一切，包括说话人的名字 |
| 锈 `#b5342a` | **只**给三样：一个人被问到停下来（沉默计数、"都停下来了"）、红头栏与密级章、抬头底下那条分隔细线 |
| 金 `#7a5f0e` `#c9a227` | 手里握着的证据、正在发言的那一席 |
| 冷蓝 `#33505f` | 沈南舟的反问 |
| 铅笔灰 | 顾言笙（2025 笔记层）与一切元信息 |

锈不碰说话人的名字，也不碰按钮——一个按钮变红会被读成"出事了"。抬头底下的细线
用同一条锈，是因为它跟着红头栏走，属于章头的一部分，不是状态记号。

悬停反馈不靠颜色：描边从 2px 加重到 3px，同时整块朝屏幕内侧挪位——侧栏挪 14，
存档格挪 (6,−6)（网格间距 12，挪 6 碰不到邻格），证据栏朝左挪 10（它的右界正好
压在 1824，往右就出安全区）。状态另有非颜色的冗余编码
（涂黑条、虚线框、回形针、装订孔），图例见游戏内"怎么读这份卷宗"。

键盘这一栏只写引擎真绑了的东西。Ren'Py 8.5.3 把 Tab 绑在 `toggle_skip` 上
（SDK `00keymap.rpy:118`），不是挪焦点——焦点只认方向键；帮助页曾经教"按 Tab 选中
证据"，照做的人一按就开始跳过正文。

## 声音：压在字下面的一条

正文一直在写声音——"窗外传来海浪撞击礁石的声音，规律而沉闷，像某种缓慢的心跳"、
"大厅里，静得能听见茶凉了、又倒进杯里的声音"。文字把耳朵叫起来了，画面是干的，
所以要有一条环境音。但它不能抢：整本是读的，不是看的。

- 环境音按地点换，地点直接由章节卡钉的那张翻拍取（`BB_AMB_BY_BG`），不在每张卡上
  重复写参数。海浪／穿堂风／雨／室内四条。
- **素材一条录音都没有**，全由 `tools/build_audio.py` 合成。网上找的"海浪"十有八九是
  纪录片片头，一放就把推理压成旅游宣传片。
- 峰值压到 -14dBFS，音乐槽默认 0.5。它在意识下面走，一抬就变成风光片。
- 环境音没有对应的画面记号（不在角上挂一条波形、也不写"此处有浪"）。这一条是取舍：
  屏幕上的每一个记号都被当作证据层的语法在用，加一个"声音在响"的图标就等于告诉玩家
  可以不看字。想知道有没有声音，设置页"声音"那一栏写了四条循环，滑杆拉到零就断。
- 音效只给"看不见的动作"配音：翻到下一章一记，拿起证据一记，逼出沉默一记闷，
  反问落下一记章。两种抵法两种响法，角章是画面上的哑动作，得有个声音对上。

三条引擎上的坑，都是实测出来的：

- 音量变量跟着混音器走。音效那条 mixer 叫 `sfx`，所以是
  `config.default_sfx_volume`；写成 `default_sound_volume` 会在 lint 阶段直接抛
  "not a known configuration variable"，并把整个跑挂。
- 判断"这一首已经在放"不能问引擎。`renpy.music.get_playing()` 在淡入还没起播、
  或自动播放一秒翻三张卡的时候会说"没在放"，于是同一条 ambience 被反复排进队列，
  听着是一阵抽气（实测第一日连排 12 次）。现在自己记 `BB_AMB_NOW`，
  并在 `config.after_load_callbacks` 里重置——读档后通道是空的，但记忆不是。
- **屏体里的 `$` 会被重跑**（预测、重绘都算一次），所以在这里配音要以"这张卡"为单位
  去重（`BB_PAGE_NOW`），不能以"这个声音"为单位。32 张扉页、32 记翻页声，
  自动播放的日志里一一对得上。

循环做在文件里（频谱法 + 整数个周期的包络），因为 Ren'Py 的 `loop=True`
只是接着重排队列，没有嵌入的循环点，文件自己接不上一听就知道。

## 跑起来

需要 [Ren'Py 8.x](https://www.renpy.org/latest.html)。

```
renpy.exe blackbird-vn          # 打开项目
renpy.exe blackbird-vn lint     # 静态检查
renpy.exe blackbird-vn compile  # 编译
```

素材缺位也能跑：`game/04_images.rpy` 里每个图像都有纯色占位，
`game/images/` 下出现同名文件就自动换成真图。

## 自检

没有测试员，所以留了几条机器能跑的检查：

```
python tools/build_fonts.py         # 改完文案先重裁字表
python tools/build_audio.py         # 只在新增/调整声音时跑（跑一次约几十秒，产物进 git）
python tools/test_logic.py          # 逻辑：反驳／沉默／循环／拼字
python tools/test_content.py        # 跨文件完整性与公平性
python tools/check_verbatim.py      # 改编不变量
python tools/check_fonts.py         # 缺字（改完文案必须重跑）
renpy.exe blackbird-vn lint         # 语法与未引用图像
cd blackbird-vn && rm -f shots/*.png && RENPY_SKIP_MAIN_MENU=1 BB_SHOT=1 BB_SHOT_DIR=shots renpy.exe .
cd blackbird-vn && BB_SHOT_TITLE=1 BB_SHOT_DIR=shots renpy.exe .   # 封面另抓一张：00_title.png
python tools/make_contact.py 4      # shots/_contact.png
cd blackbird-vn && RENPY_SKIP_MAIN_MENU=1 BB_AUTOPLAY=1 renpy.exe .   # 全六日无点击跑通
```

自动播放的日志里除 `[AUTO]` 还有 `[AMB]`（换了地点的环境音）和 `[PAGE]`（每张扉页
一记翻页声）。`[AMB]` 连续两行同一条就是抽气，`[PAGE]` 比 `[AUTO]` 的扉页多就是重跑，
见"声音"一节。

每个热点在自动播放里都会真的点掉，日志一行 `explore <地点> · 取证 N 处`；尾声打一行
`收账 证据 33／33 沉默 14／14`。这一行是"三十三条收得齐、十四处逼得出"的唯一实测证据——
以前自动播放只打一行日志就走"离开此处"，可收集性只被 `test_content.py` 静态查过，
没被真跑过一遍。改了取证点或破绽表而这一行不再是 33／14，就是漏了东西在某一处。

改了文案要先重跑 `python tools/build_fonts.py` 再跑 `check_fonts.py`：
裁剪出来的字表是静态的，新字渲染成空白而不报错。

截图脚本只用 `show screen` + `pause`，不产生需要点击的交互。唯一例外是确认框：
`modal` 的屏会把 `pause` 自己的超时事件吃掉（它压在 modal 下面），两者互锁、脚本挂住——
所以版面单独抽成不带 modal 的 `bb_confirm_panel`，`19_confirm` 截那一层。
无头截图出来是 994×559，不是 1920×1080：量的是相对位置，不是像素。

封面必须单独抓：那批图从 `start` 之后跑，跑的时候 `main_menu` 已经是 False，
所以 `01_menu` 拍到的一直是暂停菜单——标题屏上"接着上次读／挑一个存档读"两条
从来没进过任何一张图。就是补上这一张才发现 `list_slots()` 把 `_tracesave-*`、
`auto-*` 也算成"有档"（全新目录实测 18 条，玩家存的 0 条），标题屏于是永远挂着
一条读了个空档的入口。现在"接着上次读"用引擎的 `Continue()`（没档自己变灰），
"挑一个存档读"只在有 1–12 号手动档时出现。

## 出包

引擎本身没有 `dist` 这个命令——打包是 launcher 项目注册的 `distribute`：

```
renpy.exe <SDK 目录> distribute --no-update <本项目绝对路径>
```

产出在上一级的 `blackbird-dists/`：pc／win／mac／linux 四个包加一个 market 包。
加了声音之后 win 包 55MB、mac 64MB、linux 47MB，其中约 40MB 是 Ren'Py 运行时
（两个 dll），8MB 是环境音。

在 Windows 上出 mac／linux 包，引擎末尾会打印一句"unpacking and repacking the
Linux and Macintosh distributions on Windows is not supported"。这句吓不着人：
实测解包看权限位，`blackbird.app/Contents/MacOS/blackbird` 和
`blackbird-linux/.../blackbird` 都是 0755，可执行位带住了。它担心的是"更新已有的包"
（要解开旧包再打回去），而 `--no-update` 走的是整包重写。

出完包不要目测，跑审计：

```
python tools/audit_dist.py ../blackbird-dists
```

它列每个包的项目侧条目、game 文件数、音频数、授权数，并把该排除的东西逐条报出来。
两条实测得来的判据：

- `renpy/**/__pycache__` 有 180 多项，那是引擎自己带的，不算漏——所以只审 `renpy/`
  那一层之外的条目。
- `game/cache/` 里会留下 `bytecode-312.rpyb` 和 `build_info.json`：SDK 在
  `00build.rpy` 里把这两个精确名字标成了 `all`，是发行包的组成部分。本地 cache 里
  另外那几个（`py3analysis.rpyb`、`screens.rpyb`、`shaders.txt`）才是 `build.rpy`
  那条规则要挡掉的——所以审计查的是"cache 里除了这两样还有没有别的"，不是"有没有 cache"。

`game/99_shots.rpy*`、`tools/`、`shots/`、整个 `fonts_src/`、`game/saves/` 由
`build.rpy` 排除，OFL 授权文本不依赖 `fonts_src/`——`build_fonts.py` 已经把它落到
`game/fonts/LICENSE-*.txt`，跟着子集字体一起进包。
别只相信规则写上了——第一次就漏了 `99_shots.rpyc`（规则只写了 `.rpy`）。另外记着：
分类成 `None` 的整目录会让打包器不再往里走，排在它后面的"放行"规则轮不到，
所以放行要写在排除前面。

## 台词纪律

每一句台词、每一条圆桌发言都取自 `../黑鸟岛-终稿.md`，只做删节，不做增写。
新增内容一律标在旁白位（`N`），不放进任何角色的嘴里。

例外只有界面本身要说的话：序章、尾声、过场笔记、热点描述，以及数据层里的
`hit`／`miss` 旁白。台词行若确实需要自撰，行尾标 `# 自撰`，校验器会把它算进
"界面自撰"而不是"找不到出处"。

终稿是 markdown，直引号 `"…"` 用得多；界面一律排成 `“…”`。这是排版不是措辞，
校验器两边都剥掉引号再比。
