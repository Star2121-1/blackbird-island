# 《黑鸟岛：筛子》

长篇推理小说《黑鸟岛》的视觉小说改编，全本：序章 + 二十四章 + 尾声，六天一夜读完的一份卷宗。

```
序章 2025·杭州（顾言笙翻开手稿）
  第一日  ch1 抵达 → ch2 → ch3 书房（第八个名字）→ ch4 → ch5 → ch6 大厅 · 第一轮
  第二日  ch7 → ch8 → ch9 → 八仙桌 · 第二轮
  第三日  ch10 → ch11 → ch12 → ch13 → 大厅 · 第三轮
  第四日  ch14 → ch15 → ch16 → 大厅 · 第四轮
  第五日  ch17 → ch18 → ch19 → 大厅 · 第五轮
  第六日  ch20 → ch21 → ch22 → ch23 → ch24 → 合上卷宗
尾声 2025·杭州
```

每天夜里合上手稿，回到市档案馆的阅览室，读一段顾言笙的调查笔记（`game/12_days.rpy`）。

## 玩的方式和弹丸论破不一样

弹丸论破的圆桌裁决奖励"指出凶手"。这本书的地基是不可知——终稿不点名。
所以本作的胜利条件是 **逼出多少沉默**：把一条证据抵在一句话上，让说话的人停下来。

- 五轮对质，合计 41 句话（8／9／8／8／8），有东西能抵上去的是 21 句。
  抵下去会让人停下来的一共 **11 句**（每夜 2／2／3／2／2）；其余 10 句里，5 句
  翻开一页就过去，5 句是沈南舟把问题推回来。打到几处算几处。
- 反驳机会：第一轮 3 次（教学局），往后每夜 4 次——多给一次，错一次还有余地。
  用尽**不收轮**：花掉的是"还能抵几次"，不是"桌上还剩几句话"。原先三次误按就
  `done = True`，把没读到的正文和只在"第一次听到某一句"时才到手的证据一起锁死
  ——第一夜的死亡时间挂在第三句上，开局手快的人当场把自己打死，图鉴永远挂着缺一条。
  收轮这个动作只能由玩家按，代价写在他眼前（确认框直接报还剩几句没听过）。
- 失败不改变真相，只改变收尾那几句话。
- 沈南舟那一格是"反问"，不算赢：主人不会沉默，他把问题推回你手上。
  但抵中他，会拿到他亲口承认的那一句——第三十三条证据只在这里给，所以帮助页
  把这句写明了（不写，图鉴就永远差一格，而玩家不知道自己漏在哪个动作上）。
- 抵中了也不一定都是沉默：`hit_kind` 有三种——`silence`（涂黑条＋角章，计分）、
  `counter`（虚线框，反问）、`reveal`（翻开一条信息，不计分也不画停顿）。
  reveal 的结算文案末尾统一一句"这不是谁停下来。是卷宗里多翻开的一页。"，
  免得玩家读到"他没有再说"却看见零分。三类在文案上不许串味，由 `test_content.py`
  盯着：reveal 必须以那句收尾，silence 必须真的写出一个人停下（"没有再说""停了一下"
  这一类），counter 不许借用那句收尾。
- 死亡时间在第三句才到手，却要用在第二句上：一圈听完会自动回到第一句，
  桌上写"第 2 遍在听"。也可以直接点名牌跳回某个人重听。
- 有些证据只在**听过那一句**时才到手（`hears`），而"结束本轮"和"三次用尽"都会
  把没听过的句子留在桌上——这一夜之后再也回不来，图鉴永远挂着缺一条。这是设计，
  不是 bug：这本书的分数就是你逼出来的沉默。但玩家不该在看不见代价的地方签字，
  所以「结束本轮」的确认框现在报"还有几句没有听过"，三次用尽那一次的判词
  也不再跟着对质界面一起消失，而是落在结算页第一格。
- 第八个名字在第三章被读到（"我没有看清"），在第十四章正面出现时给玩家拼——
  那是**反谜题**：无论怎么拼都拿不到，一律回"我没有看清"。
  这一屏是在教玩家——这本书不让你指认谁。
- 终章把筛子交到玩家手里之后，桌上多一个动作：**并排**。挑两条证据放下，中间那一行
  只在手稿自己把它们并排写过的地方出现（`game/01_data.rpy` 的 `PAIRS`：19 对，用到 20 条）。
  这一屏**不可能被赢**，这是它存在的条件：不发证据、不动沉默数、不改成绩
  （`sel`／`line` 是 store 上的运行时变量，存盘会跟着进档，但每次进这张桌都从空桌摆起），
  所以收账那页的 33／33 与 11／11 一个数都不变；
  表和屏里不许出现裁决词（答对／答错／赢了／得分／指认……），没并排写过的一对中间
  写着"空着"而不是"不对"。玩家摆上去的是**引用**，不是结论——界面不替他得结论。
  15 条从没当过钥匙的证据里，这一轮派上活的有 9 条（`bridge_count` `cup_empty` `cup_mark`
  `envelope` `face_photo` `note` `photos` `phrase` `wet_trail`）；剩下 6 条
  （断掉的信号缆、袖口那一截烟灰、沈南舟日记·陈默、握手的那只手、手账的空白页、同一只手）
  正文没有把它们和任何东西并排写过，**故意不配**——凑一对就是界面代笔。
  用得最多的两条是位置C勘查页与立牌的记录，各 4 对。

## 基调：界面就是那份卷宗

不是"游戏套一层纸的皮"。玩家翻的是手稿本身，岛上的照片是夹进卷宗的现场快照。

- 纸面 `#eae5da` 是唯一的阅读面；深色照片只当场景，字一律落在纸上。
- 牛皮纸底纹压 0.22：再深就把 20px 的小字一起压到 2.5:1 以下了。
- 夜里不换房间，换时辰。四处夜里场景（第五章夜话那间书房、第十三章东翼那间房、
  第十九章"傍晚"之后的客房、2025 那两段灯下的杭州笔记）用的是**同一张白天底图派生**的
  夜版：机位、透视、家具逐像素对上。另画一张的代价是玩家读到"他们挪去了另一间房"——
  第六轮删掉"餐厅""船库"就是这一类错。派生五段：收掉窗外那条白天高光 → 压暗并偏色 →
  给一道有方向的光 → 按均值拉开反差 → 收四角；参数按房间给在 `build_assets.BG_NIGHT`。
  拉开反差那一段是给纸纱补的账：纱会把暗部抬平（量过，raw 22 落屏 84、raw 46 落屏 101），
  派生时不先展一档，落屏就是一张均匀的灰。客房那张是**傍晚**不是夜——那一幕的台词是
  "日头从窗缝里落进来"，同一间房在"傍晚，我回大厅"之后才换暖版。

颜色各有专司，不许串：

| 色 | 用途 |
| --- | --- |
| 墨 `#0b0d10` | 中性的一切，包括说话人的名字 |
| 锈 `#b5342a` | **只**给三样：一个人被问到停下来（沉默计数、"都停下来了"）、红头栏与密级章、抬头底下那条分隔细线 |
| 金 `#7a5f0e` `#c9a227` | 手里握着的证据、正在发言的那一席 |
| 冷蓝 `#33505f` | 沈南舟的反问 |
| 铅笔灰 | 顾言笙（2025 笔记层）与一切元信息 |

锈不碰说话人的名字，也不碰按钮——一个按钮变红会被读成"出事了"。抬头底下的细线
用同一条锈，是因为它跟着红头栏走，属于章头的一部分，不是状态记号。

悬停反馈不靠颜色：描边从 2px 加重到 3px，同时整块朝屏幕内侧挪位——侧栏挪 14，
存档格挪 (6,−6)（网格间距 12，挪 6 碰不到邻格），证据栏朝左挪 10（它的右界正好
压在 1824，往右就出安全区）。状态另有非颜色的冗余编码
（涂黑条、虚线框、回形针、装订孔），图例见游戏内"怎么读这份卷宗"。

选中态（`selected_background`）曾经和悬停走的是两套颜色，而且错的那一套更响：
引擎把 `ShowMenu`／`Preference` 这类动作命中的一律标成 selected，于是设置页里
"自动"一开就变金、Esc 侧栏当前项也变金——图例明写"金细边＝正在说话的那一位"，
菜单却满屏在喊有人在说话。现在菜单侧的选中是 `frame_chip_sel_ink.png`（双细线，
还是墨），金只留给发言席 `bb_seat` 和手里的证据 `bb_ev`；勾选项的勾也从锈改成墨。
悬停＝单粗线，选中＝双细线，两者都不动色相。

同一处漏网还有第二层，第二轮才抓到：右上角那排快捷芯片借的是 `bb_ev` 的皮，
于是也借走了它的金——点开的"设置"那颗会常亮。现在快捷栏有自己的 `bb_qk`，
选中是同一张墨色双细线；"自动"开没开也不再靠颜色说，直接把状态写进字里
（自动·开／自动·关）。顺手把那排芯片的右沿钉住（`xalign 0.95` 定的是**左沿**，
整条向右长出去七个芯片，实测右界约 1854，压过 1824 那条 5% 安全线；
加 `xanchor 1.0` 之后实测 1821）。

图例上两句说过头的也被改实了。原本写"锈色只此一处＝沉默"，可红头栏、章节卡的
"第 N 章"、封面上的"密级未解密"本来就是锈——那是卷宗自己的印刷色，不是状态；
现在写"红头是卷宗的印"。`notify` 那行提示原本刷金、图鉴里"几条未齐"的清点原本
刷锈，两者既不是席位也不是停顿，一律改成铅笔灰——表里那句"铅笔灰＝一切元信息"
终于名副其实。装订孔那条注释也改了口径：它记的是"这条证据抵上过一句"，
不是"用完了"——同一件东西当然可以再举第二次，界面没拦。

键盘这一栏只写引擎真绑了的东西。Ren'Py 8.5.3 把 Tab 绑在 `toggle_skip` 上
（SDK `00keymap.rpy:118`），不是挪焦点——焦点只认方向键；帮助页曾经教"按 Tab 选中
证据"，照做的人一按就开始跳过正文。
两条快进都不许写成"什么都能跳"：它们受设置里那一格「允许跳过」管（`_preferences.skip_unseen`），
关着时没读过的正文一句也跳不过去。帮助页和 README 现在都写这一格，README 还写清
`Ctrl` 是按住、跳的是读过的部分——只写"快进"两个字，玩家会以为它能替他读书。

## 声音：压在字下面的一条

正文一直在写声音——"窗外传来海浪撞击礁石的声音，规律而沉闷，像某种缓慢的心跳"、
"大厅里，静得能听见茶凉了、又倒进杯里的声音"。文字把耳朵叫起来了，画面是干的，
所以要有一条环境音。但它不能抢：整本是读的，不是看的。

- 环境音和音乐床按两条轴换。**地点**那一轴查表（`BB_AMB_BY_BG`／`BB_MUS_BY_BG`），
  地点直接由章节卡钉的那张翻拍取，不在每张卡上重复写参数。**情绪**那一轴由章节卡
  自己点（`mood="night"` → `BB_MOOD`），点了两路都跟着那一档走，没点的仍回落到地点表。
  剧本里也能直接换一档（`$ bb_mood("dust")`），用在**整段回到二〇二五年**的入口：杭州那
  五段笔记紧跟在过夜卡后面，卡上的"夜里的海"不该一路响进阅览室——但岛上章节里夹的一两行
  回忆不换，换了就是抽气。
  两条轴都要：同一面大厅墙（`bg_hall_ring` 钉在第六章、第八章和第一夜那张过夜卡上），
  坐着对质、"东翼不是档案室"和凌晨那扇门开了，不该是同一床。
  环境音六条：海浪／穿堂风／雨／室内／夜里的海／封存的房间。
  音乐床七张：大厅（对质的那架走音旧琴）／海上（外头没有墙，混响收短、音更稀）／
  屋里（最小的屋子，根音反而比大厅高两个半音——墙离人近）／夜（音区压到最低、拨弦最稀、
  混响最长）／
  逼近（多压一地差半音的持续音，拍音很慢）／翻手稿（二〇二五年那一头，屋子是干的）／
  终章（只剩高音区几个孤立的音，尾巴留满）。同一件乐器，换的是这一程走到哪儿了。
- 情绪档只有四档、挂在 16 张卡上（32 张的一半），刻意不做"每句一个 sting"：这本子的胜负写在
  "哪句话能被打断"上，配音已经为这个放弃过一次的标记（见人声一节），音乐同理——
  一紧张就换曲子，等于用耳朵给玩家划重点。
- 六条环境音里最亮的是雨（质心 1.7kHz，其余 76–918Hz），因为它本来就该是"沙沙"的——
  但也正因为它最亮，玩家报的"沙沙"最容易算到它头上。它的顶从最初照素材给的 6k 一路
  压到 3.4k（质心 2016 → 1715Hz），窗纸外面的雨不是打在铁皮上。穿堂风那层沙跟
  低频主体在右声道共用同一条阵风包络，两声道都用一条的话高频会粘在头顶不动。
- **素材一条录音都没有**，全由 `tools/build_audio.py` 合成。网上找的"海浪"十有八九是
  纪录片片头，一放就把推理压成旅游宣传片；现成的悬疑钢琴 loop 又太"配乐"，
  所以音乐也合成：自然小调、稀疏拨弦、慢起慢落的持续和声。
- 响度按 RMS 定，不按峰值：环境音 -32／-33／-34／-37／-33／-36dBFS，音乐床
  -30／-32／-32／-32／-31／-32／-31，音乐槽默认还要再乘 0.5。它在意识下面走，
  一抬就变成风光片。
  峰值定不得——这些床的峰均比实测 13–19dB（慢涌把包络压扁），同样写 -26dBFS 峰值，
  sea 和 room 的实际响度差 6dB。
- **曾经一直在"沙沙"，2026-11-02 才抓到。** 频谱整形的曲线函数按赫兹写（截止 320Hz
  这种），调用时传的却是 `freqs / sr`（归一化，0–0.5）：`0.5/320` 的任意次幂还是 0，
  低通退化成全通，四条"色噪声"全是白噪声；带通那一支更糟，`lo/f` 变成 3600，
  低截止项退化成正比 f^6 的高频爬升。实测当时 1.2kHz 以上占 90–99% 的能量、
  频谱质心 5.5k–9.8kHz。盘上有文件、lint 全绿、截图正常——只有耳朵听得出来。
  现在 `build_audio.py` 每条都验质心和 RMS（`check_bed`），改坏直接红：十三条
  （六环境音＋七音乐床）实测质心 76–1715Hz，各自的上限留在实测的 1.4–2.5 倍。
  上限不是拍的——白噪声在这个采样率下质心 5514Hz，最松的那道（雨 2600）离它还有
  2.1 倍，最紧的那道（封存的房间 180）离它 31 倍。
  也就是说这条闸门防得住"退化成白噪声"（那必然 2 倍以上越线），防不住"只是偏亮
  了一点"——rain 的上限只比白噪声低 2.1 倍，它本来就该是六条环境音里最亮的，那一档归耳朵。
  撤掉的接缝闸门也记在那函数的注释里：两种量法都证明分不开好坏，量不出来的
  东西不当闸，宁可留给耳朵。
- 环境音和音乐都没有对应的画面记号（不在角上挂一条波形、也不写"此处有浪"）。这一条
  是取舍：屏幕上的每一个记号都被当作证据层的语法在用，加一个"声音在响"的图标就等于
  告诉玩家可以不看字。想知道有没有声音，设置页"声音"那一栏写了合成循环与七床琴，
  「环境／音乐音量」滑杆拉到零就断。
- 音效只给"看不见的动作"配音：翻到下一章一记，拿起证据一记，逼出沉默一记闷，
  反问落下一记章。两种抵法两种响法，角章是画面上的哑动作，得有个声音对上。
- 回主菜单（`full_restart`）时环境音、音乐、人声三条声道一律无条件停。这一句写在
  `bb_amb_at_start` 里而不是"跟地点走"：重开之后地点表还没轮到钉第一条，
  按 `BB_*_NOW` 去重会失效（那几个 dict 已被 `default` 抹回 None），必须无条件停。

三条引擎上的坑，都是实测出来的：

- 音量变量跟着混音器走。音效那条 mixer 叫 `sfx`，所以是
  `config.default_sfx_volume`；写成 `default_sound_volume` 会在 lint 阶段直接抛
  "not a known configuration variable"，并把整个跑挂。
- 判断"这一首已经在放"不能问引擎。`renpy.music.get_playing()` 在淡入还没起播、
  或自动播放一秒翻三张卡的时候会说"没在放"，于是同一条 ambience 被反复排进队列，
  听着是一阵抽气（实测第一日连排 12 次）。现在自己记 `BB_AMB_NOW` 和 `BB_MUS_NOW`，
  并在 `config.after_load_callbacks` 里重置——读档后通道是空的，但记忆不是。
  两条声道（`ambience` 和引擎自带的 `music`）共用一个音量槽，注册在
  `renpy.music.register_channel("ambience", "music", True)` 的 master 上。
- **屏体里的 `$` 会被重跑**（预测、重绘都算一次），所以在这里配音要以"这张卡"为单位
  去重（`BB_PAGE_NOW`），不能以"这个声音"为单位。32 张扉页、32 记翻页声，
  自动播放的日志里一一对得上。同一只坑的另一种踩法：`BB_PAGE_NOW` 和 `BB_AMB_NOW`
  一样要在 `config.after_load_callbacks` 里清，否则读档落在哪一章，那一章的翻页声就没了。

循环做在文件里（频谱法 + 整数个周期的包络），因为 Ren'Py 的 `loop=True`
只是接着重排队列，没有嵌入的循环点，文件自己接不上一听就知道。音乐床另外三条：
和声按小节网格铺（每地两小节长、相邻两地叠一整小节）、拨弦只落在 1/4 拍的网格上、
超出循环点的尾巴圆周绕回开头、混响用圆周卷积——随便哪一条改成时域随机，接缝就露。

和声为什么叠两小节：一开始一地正好一小节，`np.hanning` 两头归零，于是每个小节接缝处
只有"正在起音的那一地"在响、上一地已经没了——整床在每个小节线上掉到零。这个坑在
混音里被拨弦填掉一半，光听混音量出来只有 5dB，把拨弦关掉、单独量和声层是 **22.9dB**
（300Hz 以下包络，500ms 窗）。叠到两小节长之后同一个量法剩 8.1dB，而那点起伏来自
和弦本身的音区差，是要的。教训：**要查一层自己的毛病，就把那一层单独拎出来量**，
混音里的数字是几层互相打掩护的数字。

## 跑起来

需要 [Ren'Py 8.x](https://www.renpy.org/latest.html)。

```
renpy.exe blackbird-vn          # 打开项目
renpy.exe blackbird-vn lint     # 静态检查
renpy.exe blackbird-vn compile  # 编译
```

素材缺位也能跑：`game/04_images.rpy` 里每个图像都有纯色占位，
`game/images/` 下出现同名文件就自动换成真图。

## 自检

没有测试员，所以留了几条机器能跑的检查：

```
python tools/build_fonts.py         # 改完文案先重裁字表
python tools/build_audio.py         # 只在新增/调整声音时跑（跑一次约几十秒，产物进 git）
python tools/test_logic.py          # 逻辑：反驳／沉默／循环／拼字
python tools/test_content.py        # 跨文件完整性与公平性
python tools/check_verbatim.py      # 改编不变量
python tools/check_fonts.py         # 缺字（改完文案必须重跑）
renpy.exe blackbird-vn lint         # 语法与未引用图像
cd blackbird-vn && rm -f shots/*.png && RENPY_SKIP_MAIN_MENU=1 BB_SHOT=1 BB_SHOT_DIR=shots renpy.exe .
cd blackbird-vn && BB_SHOT_TITLE=1 BB_SHOT_DIR=shots renpy.exe .   # 封面另抓一张：00_title.png
python tools/make_contact.py 4      # shots/_contact.png
cd blackbird-vn && RENPY_SKIP_MAIN_MENU=1 BB_AUTOPLAY=1 renpy.exe .   # 全六日无点击跑通
```

跑这些用的是系统的 Python，不是 Ren'Py SDK 里那一只——SDK 的 Python 没有 fontTools、
numpy、scipy、Pillow（实测 `check_fonts.py` 在它下面直接 `ModuleNotFoundError`）。
依赖列在 `requirements.txt`，一条 `pip install -r blackbird-vn/requirements.txt` 装齐。

`fonts_src/` 在 `.gitignore` 里（16MB 全量原件，OFL 允许再分发但没必要占仓库），
所以新克隆的机器上 `build_fonts.py` 跑不动：四份源字体逐个 `SKIP`。
现在这条路返回 1 而不是 0——以前它全 SKIP 也报成功，`game/fonts/` 里留着旧字表，
新增的字照样渲染成空白，只有下一次 `check_fonts.py` 才发现。要重裁得先从
Google Fonts / Adobe 的发布页取原件放进 `fonts_src/`：
`NotoSansCJKsc-Regular.otf`、`NotoSansCJKsc-Bold.otf`、`NotoSerifSC-wght.ttf`、
`MaShanZheng-Regular.ttf`。

自动播放的日志里除 `[AUTO]` 还有 `[AMB]`（换地点或换情绪档时的环境音）、`[MUS]`（跟着
同一处换的音乐床）和 `[PAGE]`（每张扉页一记翻页声）。`[AMB]`／`[MUS]` 连续两行同一条
就是抽气，`[PAGE]` 比 `[AUTO]` 的扉页多就是重跑，见"声音"一节。读档那一趟再各打一行
`[AMB-LOAD]`／`[MUS-LOAD]`——两条通道都得在续档后重新排上，少一条就是"有浪没琴"或
反过来。

每个热点在自动播放里都会真的点掉，日志一行 `explore <地点> · 取证 N 处`；尾声打一行
`收账 证据 33／33 沉默 11／11`。这一行是"三十三条收得齐、十一处逼得出"的唯一实测证据——
以前自动播放只打一行日志就走"离开此处"，可收集性只被 `test_content.py` 静态查过，
没被真跑过一遍。改了取证点或破绽表而这一行不再是 33／11，就是漏了东西在某一处。

终章那张"并排"桌在自动播放里也真的摆一次，日志一行 `pair seal_rec＋face_photo`
（第二十四章桌上真并排过的两件）。它在的话，`收账` 那行的 33／11 必须**一个数都没变**——
这一屏加了动作却不改成绩，靠的就是这一对同时成立；哪天 `pair` 那行在而数字涨了，
就是有人在并排屏里发了证据或记了分。这一屏的闸门是四条反方向的：
`test_content.py` 查表里的 id 都在 `EVIDENCE`（写错一名，那一对永远摆不出来）、
查每一对的两件都在**摆上桌之前**就收得到（到手日序不许晚于第六日，第六日内还要比字符偏移：
`call bb_pair_desk` 之后才 `ev_give` 的那条算迟——只看"第几天"分不开它，而桌上那条信封
正好就在第二十四章之前的第二十三章，同日只隔一章）、查屏体里没有带句号的字符串字面量（先剥 `"""…"""` 和整行注释再数，
并要求字面量不少于 10 个，免得切片切歪让闸门空转）、查表与屏里一个裁决词都没有；
另外查自动出口（`bb_auto` + `timer` + `BB_AUTO_PAIR`）在不在——缺了这一条，
`BB_AUTOPLAY` 会卡在这一屏，全六日回归当场断掉。
"这屏不可能被赢"还有一条静态的：屏体**和它下面那一层**（`bb_pair_desk` 的 label 体，
按下一个 `# ----------------` 切片并验长度非空）里出现 `ev_give`／`have.add`／`.silence`
／`bullets`／`persistent`／`renpy.save` 任一，直接失败——只查画界面的那一层是不够的，
往调用它的那一层塞一句发证据，整道闸就绕过去了。到手偏移那条判据用的也是宽的那种 `ev_give`
写法（`python:` 块里的也算），因为它原先借的是只认 `$ ev_give("…")` 的窄表，块里的到手会被当成
"这天没发过"而悄悄放行；第六日目前只有一个脚本文件，这条也钉成了闸，多了第二个就得改排序。

存读回归是同一趟跑完的第二趟：第一趟在尾声 `renpy.save("regress")` 后收工，
第二趟带 `BB_LOAD=1` 开起来就在 `start` 里读回这一档，打一行
`[LOAD] 读回 证据 33 沉默 11`。两个数都要对得上第一趟——它盯的是"读档把状态读丢了"：

```
cd blackbird-vn && RENPY_SKIP_MAIN_MENU=1 BB_AUTOPLAY=1 renpy.exe .   # 第一趟，末尾存盘
cd blackbird-vn && RENPY_SKIP_MAIN_MENU=1 BB_LOAD=1 renpy.exe .      # 第二趟，读回来
```

这条回归第一次跑就抓到一只真 bug：`have` 原先在 `init python:` 里赋成 `set()`，
运行时往里 `add`。引擎把 init 造出来的对象按"还是 init 那一个"处理，不把它的内容写进档，
于是重开游戏读档回来证据是空的（沉默数在，因为标量是重新赋值的）——玩家看到的正是
"读档把手里的证据读没了"。现在 `have` 是 `default`，`test_content.py` 里加了一条
静态闸门：init 里赋值、运行时又 add／append 的容器，必须声明成 `default`。

同一只坑的第三种形状在 `Debate` 上：五局的对象是 `default round1..5`，存档时被原样
序列化（`call screen bb_debate(d)` 时调用栈上还多一份引用，指的是同一个对象），
后加的字段不会自己长出来。早先为它写了 `after_upgrade`，
看起来像兜底，其实一次都不会执行——那个名字是 `renpy.object.Object` 的钩子，
普通 `object` 子类没人调。现在 `Debate` 自己实现 `__getstate__`／`__setstate__`，
`__version__` 随状态一起进档，旧档（没这一行）按 0 算并补 14 个字段；
`test_logic.py` 用一份抹掉字段的手搓旧档验这条路径，并能在钩子被拔掉时报 FAIL。
真跑的那一遍在两趟回归里：第一趟末尾 `renpy.save("regress")` 时这五个对象带着
`heard`／`counters` 一起进档，第二趟 `__setstate__` 走的就是恢复那条路。

改了文案要先重跑 `python tools/build_fonts.py` 再跑 `check_fonts.py`：
裁剪出来的字表是静态的，新字渲染成空白而不报错。

截图脚本只用 `show screen` + `pause`，不产生需要点击的交互。唯一例外是确认框：
`modal` 的屏会把 `pause` 自己的超时事件吃掉（它压在 modal 下面），两者互锁、脚本挂住——
所以版面单独抽成不带 modal 的 `bb_confirm_panel`，`19_confirm` 截那一层。
无头截图出来是 994×559，不是 1920×1080：量的是相对位置，不是像素。

封面必须单独抓：那批图从 `start` 之后跑，跑的时候 `main_menu` 已经是 False，
所以 `01_menu` 拍到的一直是暂停菜单——标题屏上"接着上次读／挑一个存档读"两条
从来没进过任何一张图。就是补上这一张才发现 `list_slots()` 把 `_tracesave-*`、
`auto-*` 也算成"有档"（全新目录实测 18 条，玩家存的 0 条），标题屏于是永远挂着
一条读了个空档的入口。现在"接着上次读"用引擎的 `Continue()`（没档自己变灰），
"挑一个存档读"只在有 1–12 号手动档时出现。

## 出包

引擎本身没有 `dist` 这个命令——打包是 launcher 项目注册的 `distribute`：

```
renpy.exe <SDK 目录> distribute --no-update <本项目绝对路径>
```

出包前先单独跑一条快的：

```
renpy.exe <项目目录> compile
```

`distribute` 内部有一步是给工程重编 `.rpyc` 的子进程，它在收尾时会跑
`config.quit_callbacks`——那时 `default` 语句还没落地，回调里读 `store.xxx` 就抛
`AttributeError`。子进程把错写进 `traceback.txt` 之后挂住，父进程于是永远停在
"Scanning project files..."，一行错都不往上传（实测白等 16 分钟才想到去看项目目录里的
`traceback.txt`）。`compile` 单独跑十几秒，同样的错当场报，还不会留下半个包。

产出在上一级的 `blackbird-dists/`：pc／win／mac／linux 四个包加一个 market 包。
目录名是 `build.destination` 钉死的（默认值 `{directory_name}-dists` 里带版本号）：
`config.version` 一旦从"从没生效"变成"1.0"，默认目录会悄悄变成
`blackbird-1.0-dists/`，旧目录里那五个过期包还留在原地，审计脚本对着它们照样报
all good——审计读的是目录，不是"最新的那一批"。包的文件名仍带版本
（`blackbird-1.0-win.zip`），审计按名字里有没有 `win`／`mac`／`linux`／`market`
认平台，不认整串前缀。
加了声音之后 win 包 74MB、mac 83MB、linux 64MB，其中约 40MB 是 Ren'Py 运行时
（两个 dll）；`game/audio/` 现在 17 条 wav 共 34.1MB——12.6MB 是六条环境音，21.2MB 是七床琴，
四记音效加起来只有 0.3MB。夜版那四张底图再加 0.77MB（win 74.9、mac 83.4、linux 64.6）：
比对应的白天原图还小，压暗之后 JPEG 的熵掉了，暗部整片是平的。
合成用的是**一条全局种子**（`RNG = default_rng(...)`，按表序逐条取数），所以往表里新增一条，
排在它后面的每一条都会重抽——这一轮在环境音表末尾加了两条，七床琴加四记音效的字节全变了
（长度一个字节不差，只是噪声换了个实现）。改一个音，git 里七八条 wav 一起动，不是改坏了。

在 Windows 上出 mac／linux 包，引擎末尾会打印一句"unpacking and repacking the
Linux and Macintosh distributions on Windows is not supported"。这句吓不着人：
实测解包看权限位，`blackbird.app/Contents/MacOS/blackbird` 和
`blackbird-linux/.../blackbird` 都是 0755，可执行位带住了。它担心的是"更新已有的包"
（要解开旧包再打回去），而 `--no-update` 走的是整包重写。

游戏信息在 `game/options.rpy`，别再写成 `options.txt`：Ren'Py 只加载 `.rpy`，
那份 txt 从来没生效过，于是 `config.name`／`config.version`／`config.save_directory`
全是默认值——窗口标题取目录名，关于页"版本 "后面是空的，而存档目录退化成
"解压出来那层文件夹叫什么就叫什么"（`renpy.py` 的 `path_to_saves`），玩家给文件夹
改个名，存档就"丢"了。8.5.3 的 config 里没有 `url`／`about` 这两个变量，写上去
lint 直接报 `not a known configuration variable`；项目自己的关于页在
`02_screens.rpy` 的 `screen about`。

出完包不要目测，跑审计：

```
python tools/audit_dist.py ../blackbird-dists
```

它列每个包的项目侧条目、game 文件数、音频数、授权数，并把该排除的东西逐条报出来。
两条实测得来的判据：

- `renpy/**/__pycache__` 有 180 多项，那是引擎自己带的，不算漏——所以只审 `renpy/`
  那一层之外的条目。
- `game/cache/` 里会留下 `bytecode-312.rpyb` 和 `build_info.json`：SDK 在
  `00build.rpy` 里把这两个精确名字标成了 `all`，是发行包的组成部分。本地 cache 里
  另外那几个（`py3analysis.rpyb`、`screens.rpyb`、`shaders.txt`）才是 `build.rpy`
  那条规则要挡掉的——所以审计查的是"cache 里除了这两样还有没有别的"，不是"有没有 cache"。
- 包里的 game/ **多出来**的东西也报（`EXTRA`），只有一样例外：打包时引擎自己在
  game/ 里生成的 `script_version.txt`。game/ 少文件会灰块，多文件是旧包／错规则留的，
  两个方向都得响。
- README 入口表里承诺的文件名（`blackbird.exe` / `blackbird.app` / `blackbird.sh`），
  在对应那个包里必须真的在顶层。这条是补的教训：Linux 那行以前写 `blackbird`，
  包内容审计全绿，玩家第一步就找不到能点的东西——"包里有没有 README"和
  "README 说的是不是实话"是两件事。键位与存档路径没法机器核，改 README 时手动对
  `config.keymap` 默认值和 `config.save_directory`。

`game/99_shots.rpy*`、`tools/`、`shots/`、整个 `fonts_src/`、`game/saves/` 由
`build.rpy` 排除，OFL 授权文本不依赖 `fonts_src/`——`build_fonts.py` 已经把它落到
`game/fonts/LICENSE-*.txt`，跟着子集字体一起进包。
别只相信规则写上了——第一次就漏了 `99_shots.rpyc`（规则只写了 `.rpy`）。另外记着：
分类成 `None` 的整目录会让打包器不再往里走，排在它后面的"放行"规则轮不到，
所以放行要写在排除前面。

## 台词纪律

每一句台词、每一条圆桌发言都取自 `../黑鸟岛-终稿.md`，只做删节，不做增写。
新增内容一律标在旁白位（`N`），不放进任何角色的嘴里。

例外只有界面本身要说的话：序章、尾声、过场笔记、热点描述，以及数据层里的
`hit`／`miss` 旁白。台词行若确实需要自撰，行尾标 `# 自撰`，校验器会把它算进
"界面自撰"而不是"找不到出处"。

但"旁白不查"这句只对一半：旁白里一旦出现中文引号，括号里那段就是某个具体的人
说的话，而它落在字符串参数里，`LINE_RE` 和 `STMT_RE` 都吃不到。2026-11-03 清点时
就是这么漏着三句——方廷的"它进过"、主人两句"你替我数一遍""缝在哪一册上的"，
全是界面替人物写的，README 那句"不增写一句台词"当时是假的。三句都改回正文自己的
那一拍（方廷那句落在"是从原卷宗里抽出来的"这条事实上，主人那句落在
"桌上摆着八只杯"和"他没有说那位是谁"上）：删是允许的，代笔不是。
现在 `check_verbatim.py` 第三条门扫每一对引号：要么在终稿里，要么是本作已经验过的
台词的回声（界面复述人物刚说过的字，比如"他不接“不在场”那三个字"），短于三个字的
当按钮名放行——帮助页那句"再选“反　驳”"不是台词。塞一句人物没说过的话进去，
它报 `VOICE` 并以 RC=1 收工。

终稿是 markdown，直引号 `"…"` 用得多；界面一律排成 `“…”`。这是排版不是措辞，
校验器两边都剥掉引号再比。

"一律"这两个字以前是空的：正文里还留着 15 行打字机引号（`\"自首书\"`、`'陈'`），
同一句"陈是守望者之一"在项目里有弯双、弯单、直单三种写法，帮助页上「日志」和
"图例"是同一排按钮却两种体例。现在 `test_content.py` 有一条闸门盯着：
玩家看得见的字符串里，贴着汉字的 ASCII 直引号一处不许有，`『』` 也禁（只用错过一次）；
`「」` 留着，但它只指界面元素名。判据是"贴着汉字"，所以 `Ren'Py` 那个撇号不误伤。

那一次批量改引号还顺手挖坏了四句台词（"被标注为'C'"变成"被“C”"，"第三天提交了自首书"
没了谓语）。逐字校验器抓不到：它走的是子序列，词都还在就放行，不问它们原来挨不挨着。
现在 `check_verbatim.py` 补上这条门的另一半——**删只能按小句删**：每个小句要在终稿里
整段连着出现，小句之间隔掉的那段必须含标点（说明那里本来就是两句）。它只管 verdict
认下来的行（自撰的话整句都不在正文里，不归它比），也看不见句首丢一两个字那一种
（"对'陈默'这个名字"丢了"对"）——那种写法走 `N` 旁白，本来就不逐字比对；
真要管得连"前一个字是不是标点"一起看，就会误伤"那他可能知道…"这类连接词。
把任一句改回挖坏的样子，这条会报 `CUT` 并以 RC=1 收工。

`N` 不是"谁都能套的一句"。终稿有两张嘴：岛上手稿的叙述者（`N`），和 2025 年杭州的
顾言笙（`GU`，凡 **【2025年·杭州·调查笔记】** 里的第一人称都是她）。封皮上缺掉的
"鸟"字就是走串的一例——那是她在十一月五日那条笔记里翻自己淘来的手稿说的，手稿里的
叙述者手上没有封皮；写成 `N`，等于让一个没有封皮的人抱怨封皮。旁白自撰也一样：
补的那一拍得是原著那一刻真有的动作（"第一轮散了""手里还捏着那张照片"），
不能只是把两句之间填平。

屏幕语言是这道纪律的盲区：`text "…"`、`bb_head(…)` 里的字符串不是台词行，
`LINE_RE` 和 `STMT_RE` 都吃不到——界面想代笔，没有任何一条门会响。
"并排"那一屏（见"玩的方式"）因此把内容全部留在数据层：中间那一行只能来自
`PAIRS`，而 `check_verbatim.py` 第四条门逐条比对 `PA("a", "b", "句")` 里的句子，
用的规则比台词那道**更严**——`norm(整句)` 必须是终稿里*连着*出现的一段，
不许子序列、不许把两个小句从不同的章里拼起来（台词那道允许小句之间隔段，
这一道不允许：并排那一行是对原著的引用，引用要整段照搬）。
屏体侧则由 `test_content.py` 钉住：并排屏里带句号的字符串字面量一个不许有
（长句一律回数据层），切片先剥 `"""…"""` 和整行注释再查、并要求字面量不少于 10 个，
免得闸门因为切歪了而空转。
那一行打印出来时外面包着一对弯引号——表里有几条本身就是某个人说出来的
（"……我存过"），不加引号会读成旁白替游戏下的判断；引号由屏幕包，
所以闸门查的是"屏上只打印 `line` 这一个变量"，不是"屏上有一句现成的话"。
